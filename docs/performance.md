# Codex Quota v1.0.2 性能审查

日期：2026-10-20。对照版本：已发布的 v1.0.1（64 位 AnyCPU），与本次 v1.0.2（AnyCPU / 32 位优先）。所有结果来自本机实测。MiB = 1048576 字节。

## 结果

| 指标 | v1.0.1 | v1.0.2 | 变化 |
| --- | ---: | ---: | ---: |
| 实际日志，启动后 3 秒私有工作集 | 41.660 MiB | 12.691 MiB | −69.5% |
| 实际日志，30 秒加速刷新后私有工作集 | 43.957 MiB | 15.801 MiB | −64.1% |
| 同一 30 秒场景，私有提交 | 65.676 MiB | 22.738 MiB | −65.4% |
| 同一 30 秒场景，GDI / USER 资源 | 127 / 75 | 18 / 21 | 背景常驻对象减少 |
| 固定日志，100 次强制扫描累计托管分配 | 2230.948 MiB | 15.910 MiB | −99.3% |
| 同一强制扫描耗时 | 1965 ms | 1047 ms | −46.7% |
| 同一强制扫描 CPU 时间 | 2046.875 ms | 1000.000 ms | −51.1% |
| 固定日志，500 次缓存刷新分配 | 9.047 MiB | 6.938 MiB | −23.3% |
| 同一缓存刷新耗时 | 49 ms | 66 ms | 单次差约 0.034 ms |

缓存路径没有声称更快：其中仍会按原策略枚举文件以发现新增、删除和修改，32 位文件系统调用开销与测量噪声会影响微小耗时。主要改善来自全量扫描时的分配、解析和垃圾回收压力，以及后台窗口与图标资源。

用户截图约 44.4 MB，与最初读取到的私有工作集约 44.4 MiB一致。总工作集、私有工作集和私有提交是不同指标，本文没有混用它们。私有工作集按 [QueryWorkingSet](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-queryworkingset) 的非共享驻留页统计，接近任务管理器进程内存列；系统压缩、共享页和统计时间可能造成小差异。

## 方法

- 保存原 v1.0.1 EXE，两个版本在独立宿主中调用相同读数与托盘代码，使用相同 DPI 清单。
- 扫描基准使用同一套 32 份固定合成 JSONL 文件：多字节文本和有效额度事件，不含用户会话内容。先预热一次，再做 100 次强制扫描及 500 次缓存刷新。
- 累计分配使用 AppDomain.MonitoringTotalAllocatedMemorySize，CPU 使用进程 CPU 时间。累计分配并不等于同时占用的内存。
- 常驻对照同时读取同一本机真实会话目录，测试宿主临时将刷新定时器设为 100 ms，观察 30 秒；这是加速测试，产品的默认 30 秒和用户自定义间隔不变。
- 性能宿主及产品都未调用 GC.Collect、EmptyWorkingSet 或 SetProcessWorkingSetSize。没有通过换页或裁剪工作集制造较低读数。现有图标泄漏测试为检查原生句柄，会在测试进程中显式收集垃圾，它不参与性能对照。
- 原始数值见 performance_metrics.csv。tools/PerformanceBench.cs 接受 reader、tray、quiet 模式和日志目录，reader 可附加强制扫描次数。quiet 30 秒自动退出，tray 会额外循环开关详情与设置窗口。

### 复现固定日志测试

先分别构建或取得两个版本 EXE，再执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\measure-performance.ps1 -Baseline .\work\previous_version\CodexQuota.exe -Candidate .\CodexQuota.exe
```

脚本只生成合成日志，默认不访问真实会话正文，不写用户设置。两版宿主按各自架构构建，各自跑扫描、窗口循环和 30 秒加速空闲场景；数值保存在项目 work/performance_runs 下。参数可覆盖两版宿主的平台以做相同位数对照。实际会话目录的高级测试可自行编译 PerformanceBench.cs 并传入目录。

## 修改

1. 日志读取改为复用单个有界字节缓冲，去掉每块和每行的重复数组、无关 UTF-8 字符串与整树字典分配。异常长行之后不保留超大缓冲。
2. 使用 .NET Framework 自带流式 JSON 读取器，仅提取额度相关字段，跳过未知内容。补充原始 JSON 括号与引号完整性检查，避免系统读取器把缺失结尾的事件容错成有效数据。
3. 配置和诊断使用系统数据契约 JSON，保持现有字段、默认值和旧配置兼容，避免产品加载 Web 序列化栈。
4. 背景启动只创建小型消息分派控件；首次需要详情时再创建原界面。隐藏面板即释放专用双缓冲，重新显示时照常绘制。
5. 图标只缓存当前圆环与数字两张，额度、月相、到期状态或主题改变时才重画；读数年龄和提示文字仍按原刷新节奏更新。
6. 自建字体显式释放，固定月相系数复用。默认使用 32 位优先运行，减少 CLR、对象与指针开销；保留 -Platform anycpu 供其他构建需要。

## 验收与使用体验

- 45 项自动化测试通过，保留原 36 项并新增流式字段顺序、Unicode 与跳过字段、完整事件、重复键、长行缓冲、配置往返、诊断字段、图标复用、隐藏释放和背景懒加载检查。
- 设置窗口 100%、125%、150%、200% 预览与图标逐像素一致。
- 深色、浅色、空态、陈旧读数详情面板，排除会变化的时间及版本文字区域后逐像素一致。
- 常用间隔、自定义间隔、低额度颜色、月相、读数时间、倒计时、手动强制刷新、目录选择、登录自启、诊断、单实例和快捷键继续保留。
- 32 位优先只改变运行方式，日志仍使用 64 位文件偏移和原有有界读取。程序的系统要求仍是 Windows 10 / 11 + .NET Framework 4.8，无新增依赖。

## 边界

内存受日志数量、窗口状态、CLR 缓存、系统内存压力和运行时间影响，不保证所有机器固定为 15.8 MiB。30 秒加速对照及循环资源测试不等同于数天常驻验证。日志内部格式未来仍可能需要适配。额度数据仍是本地日志快照，不是服务端实时查询。
